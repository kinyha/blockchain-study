# Урок 8: Proof-of-Work и майнинг

## Введение

Это, пожалуй, самый важный урок. **Proof-of-Work** — это то, что делает blockchain **децентрализованным** и **безопасным**.

Без него blockchain — просто связанный список, который может изменить любой. С ним — неизменяемый реестр, защищённый вычислительной мощностью всей сети.

---

## Проблема: кто добавляет блоки?

### Централизованный вариант

Один сервер решает, какие транзакции валидны:
```
Все транзакции → Центральный сервер → Blockchain
```

Проблемы:
- Единая точка отказа
- Цензура транзакций
- Нужно доверять серверу

### Децентрализованный вариант

Тысячи узлов, каждый хочет добавить свой блок:
```
Узел 1: "Мой блок лучше!"
Узел 2: "Нет, мой!"
Узел 3: "А я первый!"
```

Как достичь **консенсуса** без центра?

---

## Задача византийских генералов

### Постановка

Несколько армий окружили город. Генералы могут общаться только через посыльных. Нужно:
1. Договориться об общем решении (атаковать/отступать)
2. При условии, что некоторые генералы — **предатели**

### Почему это сложно?

```
Генерал A → Генералу B: "Атакуем!"
Генерал A → Генералу C: "Отступаем!"  (A — предатель)

B думает: атакуем
C думает: отступаем
Результат: поражение
```

### Решение Сатоши

**Proof-of-Work** решает эту задачу экономически:
- Чтобы "соврать", нужно потратить реальные ресурсы (электричество)
- Честным быть выгоднее, чем атаковать
- Даже если 49% узлов — злоумышленники, сеть работает

## Что такое Proof-of-Work?

### Идея

Чтобы добавить блок, нужно **доказать**, что ты проделал вычислительную работу. Это доказательство:
- **Сложно создать** (требует миллиардов попыток)
- **Легко проверить** (одна операция хэширования)

### Механизм

```
Данные блока + nonce → SHA-256 → Hash

Если hash начинается с N нулей → блок валиден
Иначе → nonce++, повторить
```

**nonce** (number used once) — счётчик, который перебираем.

### Пример

Difficulty = 4 (hash должен начинаться с "0000")

```
nonce=0: hash = "8a3b2c1d..." ❌
nonce=1: hash = "f4e5d6c7..." ❌
nonce=2: hash = "0b1a2c3d..." ❌
...
nonce=834756: hash = "0000a8f3..." ✅ Нашли!
```

В среднем нужно 16⁴ = 65,536 попыток для 4 нулей.

---

## Сложность (Difficulty)

### Что это?

**Difficulty** определяет, сколько вычислительной работы нужно для нахождения блока.

```
Difficulty 1: hash < 00ffffff...  (~16 попыток)
Difficulty 4: hash < 0000ffff...  (~65,000 попыток)
Difficulty 8: hash < 00000000f... (~4 млрд попыток)
```

### Как выражается в Bitcoin?

Bitcoin использует **target** — максимальное значение hash:

```
target = 0x00000000ffff0000000000000000000000000000000000000000000000000000

Валидный hash должен быть меньше target.
```

Difficulty = max_target / current_target

### Динамическая подстройка

Bitcoin **автоматически** корректирует сложность каждые 2016 блоков (~2 недели):

```
Если блоки создавались быстрее 10 минут → difficulty ↑
Если медленнее 10 минут → difficulty ↓
```

Цель: **стабильные 10 минут** между блоками, независимо от мощности сети.

### Историческая динамика

```
2009: Difficulty = 1 (CPU mining)
2010: Difficulty ~ 100 (GPU появились)
2013: Difficulty ~ 10,000,000 (ASIC революция)
2024: Difficulty ~ 80,000,000,000,000 (80 триллионов!)
```

Сегодня для нахождения одного блока Bitcoin нужно ~10²² (10 секстиллионов) хэшей.

## Экономика майнинга

### Награда за блок

Майнер, нашедший валидный блок, получает:
1. **Block reward** — новые монеты (сейчас 3.125 BTC)
2. **Transaction fees** — комиссии всех транзакций в блоке

### Halving (халвинг)

Block reward уменьшается вдвое каждые 210,000 блоков (~4 года):

```
2009: 50 BTC
2012: 25 BTC
2016: 12.5 BTC
2020: 6.25 BTC
2024: 3.125 BTC
2028: 1.5625 BTC
...
2140: 0 BTC (последний Bitcoin добыт)
```

Всего будет 21,000,000 BTC. Не больше, не меньше.

### Затраты на майнинг

```
Доход = Block reward × Цена BTC + Fees
Расход = Электричество + Оборудование + Охлаждение + Аренда

Прибыль = Доход - Расход
```

Майнинг выгоден, только если прибыль > 0. Это создаёт **равновесие**: если цена BTC падает → майнеры уходят → difficulty падает → оставшимся выгоднее.

### Энергопотребление

Bitcoin потребляет ~100-150 TWh/год — как небольшая страна.

Аргументы "за":
- Обеспечивает безопасность $1+ трлн активов
- Стимулирует развитие возобновляемой энергетики
- Использует "stranded" энергию (которая бы пропала)

Аргументы "против":
- Огромный углеродный след
- Ресурсы можно использовать продуктивнее
- Proof-of-Stake достигает того же без энергозатрат

## Эволюция оборудования

### CPU (2009-2010)

Первые майнеры использовали обычные процессоры:
```
Intel Core i7: ~10 MH/s (10 млн хэшей/сек)
```

### GPU (2010-2013)

Видеокарты параллельны и быстрее для SHA-256:
```
NVIDIA GTX 1080: ~30 MH/s
AMD RX 580: ~25 MH/s
```

### FPGA (2011-2012)

Программируемые чипы, эффективнее GPU:
```
~100 MH/s при меньшем энергопотреблении
```

### ASIC (2013-сейчас)

**Application-Specific Integrated Circuit** — чип, созданный только для SHA-256:
```
Antminer S21: 200 TH/s (200 триллионов хэшей/сек!)
```

ASIC в 20,000,000 раз быстрее CPU. Майнинг на CPU/GPU давно нерентабелен.

### Mining Pools

Шанс найти блок в одиночку → 0%. Решение — **пулы**:
```
1000 майнеров объединяются
Находят блоки чаще
Делят награду пропорционально мощности
```

Топ пулы: Foundry USA, AntPool, F2Pool, ViaBTC.

## Атаки на Proof-of-Work

### 51% атака

Если злоумышленник контролирует >50% мощности сети, он может:
1. **Double-spend** — потратить монеты дважды
2. **Цензура** — не включать определённые транзакции
3. **Реорганизация** — переписать последние блоки

**НЕ может:**
- Украсть чужие монеты (нужны приватные ключи)
- Создать монеты из воздуха (нарушит консенсус)
- Изменить старые блоки (экспоненциально сложнее)

### Почему 51% атака невыгодна?

Для Bitcoin:
- Стоимость оборудования: ~$10+ млрд
- Электричество: ~$20 млн/день
- При успешной атаке цена BTC рухнет
- Оборудование станет бесполезным

Выгоднее честно майнить.

### Selfish Mining

Майнер находит блок, но не публикует. Продолжает строить приватную цепь. Когда публичная цепь догоняет — публикует свою.

Работает при 25-33% мощности, но сложно в реализации.

## Альтернативы Proof-of-Work

### Proof-of-Stake (PoS)

Вместо вычислительной мощности — **залог монет**:
```
Чем больше монет заложено → выше шанс создать блок
```

Используется: Ethereum (с 2022), Cardano, Solana, Polkadot

Плюсы:
- Энергоэффективность (~99.9% меньше энергии)
- Не нужно специальное оборудование

Минусы:
- "Rich get richer" — богатые получают больше
- Nothing-at-stake problem
- Меньше протестирован временем

### Другие механизмы

| Механизм | Идея | Примеры |
|----------|------|---------|
| Proof-of-Authority | Известные валидаторы | Частные сети |
| Proof-of-Space | Выделенное место на диске | Chia |
| Proof-of-Burn | Сжигание монет | Slimcoin |
| Delegated PoS | Голосование за делегатов | EOS, Tron |

## Наша реализация

### Добавляем nonce в Block

```java
public class Block {
    // ... существующие поля
    private long nonce;

    public String calculateHash() {
        String input = index + timestamp + data + previousHash + nonce;
        return HashUtil.sha256(input);
    }
}
```

### Класс ProofOfWork

```java
public class ProofOfWork {
    private int difficulty;  // количество ведущих нулей

    public void mine(Block block) {
        String target = getTarget();  // "0000" для difficulty=4
        while (!block.getHash().startsWith(target)) {
            block.incrementNonce();
            block.updateHash();
        }
    }

    public boolean isValidProof(Block block) {
        return block.getHash().startsWith(getTarget());
    }
}
```

### Демо сложности

```
Difficulty 2: ~0.001 сек (256 попыток)
Difficulty 4: ~0.01 сек (65,536 попыток)
Difficulty 5: ~0.1 сек (1 млн попыток)
Difficulty 6: ~1 сек (16 млн попыток)
```

Для учебных целей используем difficulty 4-5.

import com.study.blockchain.core.Block;

public class ProofOfWork {

    private final int difficulty;

    public ProofOfWork(int difficulty) {
        this.difficulty = difficulty;
    }

    public String getTarget() {
        // Верни строку из difficulty нулей: "0000" для difficulty=4
    }

    public void mine(Block block) {
        String target = getTarget();
        block.setNonce(0);
        block.updateHash();

        while (!block.getHash().startsWith(target)) {
            block.incrementNonce();
            block.updateHash();
        }
    }

    public boolean isValidProof(Block block) {
        return block.getHash().startsWith(getTarget());
    }

    public int getDifficulty() { return difficulty; }
