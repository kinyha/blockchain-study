# Урок 6: Кошельки и криптографические ключи

## Введение

В предыдущем уроке мы создали транзакции с `PublicKey`. Но откуда берутся эти ключи? Как доказать, что именно ты владеешь монетами?

Ответ — **криптографический кошелёк (Wallet)**.

---

## Асимметричная криптография: основа всего

### Симметричная vs Асимметричная

**Симметричная криптография** — один ключ для шифрования и расшифровки:
```
Сообщение + Ключ → Шифр → Ключ → Сообщение
```
Проблема: как безопасно передать ключ?

**Асимметричная криптография** — два связанных ключа:
```
Приватный ключ (secret)  ←→  Публичный ключ (public)
```

Магия в том, что:
1. Зашифрованное публичным ключом → расшифровывается только приватным
2. Подписанное приватным ключом → проверяется публичным
3. По публичному ключу **невозможно** вычислить приватный

### Как это работает математически?

В основе — **задачи, которые легко решить в одну сторону, но почти невозможно в обратную**.

**RSA** (1977) — основан на сложности факторизации больших чисел:
```
Легко: 17 × 23 = 391
Сложно: 391 = ? × ?  (для огромных чисел)
```

**ECDSA** (используется в Bitcoin/Ethereum) — основан на эллиптических кривых:
```
Легко: k × G = P  (умножение точки на скаляр)
Сложно: P / G = k  (дискретный логарифм на кривой)
```

## ECDSA: выбор криптовалют

### Почему не RSA?

| Критерий | RSA-3072 | ECDSA-256 |
|----------|----------|-----------|
| Размер ключа | 3072 бит | 256 бит |
| Размер подписи | ~384 байт | ~64 байт |
| Скорость подписи | Медленнее | Быстрее |
| Безопасность | Эквивалентная | Эквивалентная |

При **равной безопасности** ECDSA даёт ключи в 12 раз короче. Это критично для blockchain, где каждый байт — это место в блоке и комиссия.

### Эллиптическая кривая secp256k1

Bitcoin использует кривую **secp256k1**:
```
y² = x³ + 7  (mod p)

p = 2²⁵⁶ - 2³² - 977  (огромное простое число)
```

Это не случайный выбор. secp256k1:
- Была создана до Bitcoin (нет "backdoor" от разработчиков)
- Оптимизирована для быстрых вычислений
- Широко проверена криптографами

### Генерация ключей

```
1. Случайное число k (256 бит) → Приватный ключ
2. k × G = P → Публичный ключ (точка на кривой)

G — фиксированная "генераторная" точка на кривой
```

Приватный ключ — просто случайное 256-битное число. Пространство настолько огромно (2²⁵⁶ вариантов), что коллизия практически невозможна.

## Адреса в Bitcoin

### От публичного ключа к адресу

Публичный ключ — это 65 байт (или 33 в сжатом виде). Слишком длинно для удобства. Поэтому создаётся **адрес**:

```
Публичный ключ (65 байт)
    ↓ SHA-256
Hash1 (32 байт)
    ↓ RIPEMD-160
Hash2 (20 байт)
    ↓ Base58Check кодирование
Адрес: 1BvBMSEYstWetqTFn5Au4m4GFg7xJaNVN2
```

### Зачем такая цепочка?

1. **SHA-256** — криптостойкость
2. **RIPEMD-160** — сокращение до 20 байт (экономия места)
3. **Base58Check** — человекочитаемый формат без похожих символов (0/O, l/I)

### Форматы адресов

| Префикс | Тип | Пример |
|---------|-----|--------|
| 1... | Legacy (P2PKH) | 1BvBMSEYstWetqTFn5Au4m4GFg7xJaNVN2 |
| 3... | Script (P2SH) | 3J98t1WpEZ73CNmQviecrnyiWrnqRhWNLy |
| bc1... | SegWit (Bech32) | bc1qar0srrr7xfkvy5l643lydnw9re59gtzzwf5mdq |

Ethereum использует проще: `0x` + последние 20 байт от Keccak-256(publicKey).

## Seed фразы и HD-кошельки

### Проблема множества ключей

Для приватности рекомендуется использовать новый адрес для каждой транзакции. Но как хранить тысячи приватных ключей?

### BIP-39: Мнемоническая фраза

12-24 слова, из которых **детерминированно** генерируются все ключи:

```
abandon abandon abandon abandon abandon abandon
abandon abandon abandon abandon abandon about
```

Слова берутся из стандартного словаря (2048 слов). 12 слов = 128 бит энтропии.

### BIP-32: Иерархические кошельки (HD)

Из одного seed генерируется **дерево ключей**:

```
Master Key (из seed фразы)
├── Account 0
│   ├── External (получение)
│   │   ├── Address 0
│   │   ├── Address 1
│   │   └── ...
│   └── Internal (сдача)
│       ├── Address 0
│       └── ...
├── Account 1
│   └── ...
```

Преимущество: достаточно сохранить seed фразу, все ключи восстанавливаются.

## Безопасность кошелька

### Что защищать?

**Приватный ключ = деньги**. Кто знает приватный ключ — владеет монетами.

### Типы кошельков по безопасности

| Тип | Где ключи | Удобство | Безопасность |
|-----|-----------|----------|--------------|
| Hot wallet (биржа) | На сервере | ★★★★★ | ★☆☆☆☆ |
| Mobile wallet | На телефоне | ★★★★☆ | ★★☆☆☆ |
| Desktop wallet | На компьютере | ★★★☆☆ | ★★★☆☆ |
| Hardware wallet | Отдельное устройство | ★★☆☆☆ | ★★★★☆ |
| Paper wallet | На бумаге | ★☆☆☆☆ | ★★★★★* |

*При правильном создании и хранении

### Атаки на кошельки

1. **Malware** — кейлоггеры, подмена адресов в буфере
2. **Phishing** — поддельные сайты кошельков
3. **Social engineering** — "техподдержка" просит seed фразу
4. **Physical** — кража устройства, подсматривание
5. **Supply chain** — заражённые hardware wallets

### Правила безопасности

1. **Никогда** не вводи seed фразу на сайтах
2. **Никогда** не делай скриншоты seed фразы
3. Проверяй адрес получателя **посимвольно**
4. Используй hardware wallet для крупных сумм
5. Тестируй восстановление из seed ДО отправки средств
